# 临床采集 · OCR 归档原型

这是一个纯客户端、移动端优先的临床资料拍照归档原型：

- 使用设备摄像头拍照，或从相册导入图片
- 默认使用本地 PaddleOCR.js PP-OCRv6 small；保留 Tesseract.js 作为可选备用引擎
- 自动提取识别结果里的常见数字/单位，支持人工校对
- 首版资料类型：血常规、肝肾功能、止凝血、CT、彩超
- 支持门诊病历、住院病历、出院小结、处方/用药、病理报告、心电图等常见文本资料
- 以个人/患者姓名或病案/就诊号为主键归档，同一个人的多份资料会自动分组显示
- OCR 后自动识别个人姓名、住院号、门诊号、病案号和病历号；识别不到时可人工填写
- 根据 OCR 关键词自动判断资料类型；检验单归纳常见项目/结果/单位/参考范围，CT/彩超归纳检查部位/所见/印象或结论
- 检验单按 OCR 表格行动态读取全部指标，不再限制为预设项目；同时保留项目、英文缩写、结果、参考范围、单位、异常提示和识别置信度
- OCR 结果表支持人工直接修改项目名称、英文缩写、结果、参考范围、单位和异常提示；嗜酸性粒细胞会按上下文规范为 `EO%`（百分比）或 `EO#`（绝对数）
- 针对当前医院报告格式内置缩写校正词典，覆盖血常规的 WBC、NEUT%/NEUT#、LYMPH%/LYMPH#、EO%/EO#、BASO%/BASO#、RBC、HGB、HCT、MCV、MCH、MCHC、RDW-CV、RDW-SD、PLT、PCT、PDW、MPV、P-LCR，以及肝肾功能和止凝血常见缩写；未知项目仍保留 OCR 原文
- 增加急性阑尾炎病例现场采集面板：按资料类型展开患者/纳入、术前临床、术前实验室、术前影像、术中 WSES、手术与术后结局字段；OCR可先填入可识别内容，人工字段支持边采集边填写，并自动保存未完成草稿
- 研究方案固定为：纳入所有接受腹腔镜探查并尝试阑尾切除的急性阑尾炎患者（含中转开腹）；`study_id` 与 `index_episode` 用于防止重复住院号导致的数据泄漏，`perforation_primary` 是术中主要结局，不再作为术前资料归档门槛
- 穿孔相关证据单独记录：综合判断、穿孔部位/范围、术中主要结局、坏死位置、蜂窝织炎/炎性包块、脓肿及最大径、局限/弥漫性腹膜炎、污染性质、游离粪石和穿孔类型；缺少范围或资料不全时可记录 Unknown 原因、双人复核和最终仲裁分级
- 按 WSES/PAMAP-W 研究结构把术前预测变量和术中/术后结局分开；术前化验和影像可注明抗生素前/后及具体时间，原始实验室动态指标、单位和采血时间保留，NLR/PLR/SIRI/PNI等衍生指标不在采集时替代原始值
- 病理诊断和病理穿孔单独保存，不能替代术中 `perforation_primary`；所有无法确定的分级均保留 Unknown 原因和复核意见
- 腹腔镜视频/照片默认按“无”记录；无视频时由机器依据术中记录 OCR 和结构化术中所见生成 WSES 分级建议，并同时保存机器输入来源、建议待确认状态和人工修改痕迹，便于按预先规定的机器规则进行科研归档
- 阑尾炎研究字段按同一 `study_id`（同一 index episode）的多份资料合并到研究表；不同 episode 即使姓名或住院号相同也可用不同 `study_id` 分开，保留有/无/未检查/未记录/未描述/不确定等状态，不把未提及误判为无
- 资料与图片保存在当前浏览器的 IndexedDB；不对接医院系统、不上传服务器
- 支持标题、资料类型、备注、搜索、筛选、详情查看、删除和 JSON 导出
- 支持在 HTTPS 网页中直接扫描电脑页面：选择浏览器标签页、窗口或整个屏幕后，可连续截取页面并进入现有 OCR 流程；屏幕内容只在本机处理，不采集音频
- 支持导出临床数据收集科研数据包 `.xlsx`：包含病例/资料/指标基础表，以及“患者与纳入信息”“术前临床资料”“术前实验室指标”“术前影像资料”“术中结局_WSES”“手术与术后结局”六张研究表和“阑尾炎字段字典”；同一 `study_id` 的多份资料汇总到同一病例ID
- 归档前必须勾选人工复核；病例卡片、资料详情和导出表会保留“人工已复核/待人工复核”状态
- 支持导出 JSON 原始备份，也支持在另一台设备导入备份并按记录 ID 合并恢复
- 档案区显示当前记录数和浏览器存储占用，便于在连续采集时及时备份
- “病例主表”按患者/研究编号归档；“资料记录表”一份检查资料一行；“指标明细表”一项识别指标一行，不预设血常规或肝功能项目清单，所有实际识别到的指标都进入长表
- 每项指标同时保留结果原值、可分析数值、单位、参考范围、异常提示、OCR 置信度、复核状态和来源资料，适合后续在 Excel/WPS 中筛选、清洗和统计
- OCR 前会保留原图，并生成整图、姓名/编号表头、指标区域等增强副本；识别后按原图坐标去重合并，归档时保存校对后的 OCR 原文、总结、全部结构化指标、数字和原始照片
- 多张图片会逐张识别并在 OCR 原文、指标表和导出包中保留“来源页”；多份同类检验单不会因第一张报告的页脚而提前停止解析
- 多张图片会按页分别评估识别质量，仅对缺少个人信息或指标不足的页面补跑表头/重点区域，减少等待时间并避免一张好图片掩盖另一张漏识别
- 研究编号可根据已识别的姓名/病案号自动生成稳定的 `CASE-XXXXXXXX`，同一患者的后续资料默认归入同一病例；手动修改后不再自动覆盖
- OCR 采用快速路径：先跑整图和表头，姓名/编号或指标不足时才补跑重点区域；本地 Service Worker 会缓存已使用的 OCR 运行时和 PP-OCRv6 small 模型，重复识别无需重新下载
- 手机拍电脑屏幕时会自动检测报告页、透视矫正、去摩尔纹并补跑局部自适应/二值化分支；自动模式发现长串拉丁乱码或身份信息缺失时，会在浏览器已加载备用 OCR 的条件下做质量对比，不会盲目覆盖较好的结果
- 已归档资料详情中可直接查看结构化指标和复制归档总结；导出的 JSON 也包含这些字段，可作为原始备份
- 归纳区提供“科研摘要、全部指标清单、异常/待复核优先、影像三段式、原文重点”模板；档案区提供按个人的一行式科研汇总和复制到 Excel 功能

## 本地运行

建议使用本地 HTTP 服务，以获得摄像头权限和 Service Worker 能力：

```powershell
python -m http.server 8080
```

然后打开 `http://localhost:8080`。

如果页面仍显示旧版提示，先关闭旧标签页，再重新打开地址；电脑端可使用 `Ctrl+F5` 强制刷新，以加载最新的本地脚本和识别规则。

当前 PP-OCRv6 small 检测/识别模型、PaddleOCR.js SDK、OpenCV.js、js-yaml、Clipper、SheetJS 和 ONNX Runtime Web WASM 文件均随项目放在本地 `models/` 与 `vendor/`，核心 OCR 和 Excel 导出不依赖 CDN，也不会访问百度 BCE 模型地址。PaddleOCR 官方浏览器 SDK 返回识别文字、文字框和置信度。

### 本机高精度 OCR（推荐电脑端连续采集使用）

如果手机拍摄电脑屏幕时浏览器 OCR 仍然漏字或把中文识别成乱码，可使用项目内的 RapidOCR + PP-OCRv5 server 本机识别层：

1. 首次联网时双击 `local-ocr/准备高精度OCR环境.cmd`，安装依赖并下载模型。
2. 日常双击 `local-ocr/启动高精度本机版.cmd`，浏览器会自动打开 `http://127.0.0.1:8765/index.html`。
3. 网页会自动选择“本机高精度 OCR（PP-OCRv5 server）”；仍可一次上传多张图片，结果继续进入个人归档、指标表和 Excel 导出流程。

本机服务只监听 `127.0.0.1`，图片不会进入医院服务器或外部 GPT 接口。首次准备模型后可断网使用；GitHub Pages 地址仍保留为无需本机服务的浏览器 OCR 版本。

## 重要限制

这是功能原型，不是经过医疗合规认证的电子病历系统。自动类型识别、个人信息提取和归纳采用本地关键词与规则，不代表诊断意见；“指标明细表”中的每项指标默认标记为“待人工核对”，不能直接作为最终科研数据库。导出包为便于本机链接而保留姓名和病案/就诊号，对外共享或进入科研分析前必须按研究方案完成去标识化、字段定义、人工复核和审计。浏览器清理站点数据、卸载浏览器或更换设备可能导致本机档案丢失。正式使用前应增加设备级加密、访问口令/生物认证、可靠的本地备份与审计机制。
